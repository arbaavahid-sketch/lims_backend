# نقش‌ها و دسترسی‌ها — آزمایشگاه تندیس (TPPC)
# Roles & Access Control

هدف: هر کارمند فقط با نقش لازم کار کند و از حساب `admin` برای کار روزمره
استفاده نشود. این مورد یکی از الزامات ISO/IEC 17025 (بی‌طرفی و تفکیک وظایف) است.

> Goal: each staff member works with only the role they need; `admin` is used
> **only** for system configuration, never for daily work.

---

## ۱) نقش‌های موجود در سیستم (Native SENAITE roles)

این نقش‌ها در همین بیلد فعال‌اند (منبع: `rolemap.xml`):

| نقش (Role) | برای چه کسی | چه کاری می‌تواند بکند |
|---|---|---|
| **LabManager** | مدیر آزمایشگاه / مدیر فنی | همه‌چیز به‌جز تنظیمات سرور؛ مدیریت کامل نمونه‌ها، روش‌ها، کاربران، امور مشتریان |
| **LabClerk** | پذیرش / کارمند دفتری | ثبت نمونه و مشتری، ورود اطلاعات، **دیدن و پاسخ امور مشتریان** |
| **Analyst** | کارشناس آزمون | انجام آزمون و **ثبت نتیجه** (Submit) |
| **Verifier** | تأییدکنندهٔ نتایج | **تأیید نتیجه** (Verify) — باید فردی جز آنالیست باشد |
| **Sampler** | نمونه‌بردار | ثبت نمونه‌برداری |
| **SamplingCoordinator** | هماهنگ‌کنندهٔ نمونه‌برداری | برنامه‌ریزی و تخصیص نمونه‌برداری |
| **Preserver** | مسئول نگهداری نمونه | ثبت نگهدارنده/شرایط نگهداری |
| **Publisher** | صادرکنندهٔ گزارش | انتشار و ارسال گزارش نهایی به مشتری |
| **RegulatoryInspector** | ممیز / بازرس (فقط خواندنی) | مشاهدهٔ همه‌چیز بدون امکان تغییر — برای ممیزی |
| **Manager** | فقط admin سیستم | تنظیمات کل سیستم؛ برای کار روزمره استفاده نشود |

---

## ۲) نکتهٔ کلیدی ISO 17025 — تفکیک آنالیست و تأییدکننده

در استاندارد ۱۷۰۲۵، **کسی که آزمون را انجام می‌دهد نباید همان کسی باشد که
نتیجه را تأیید می‌کند**. بنابراین:

- به کارشناس آزمون فقط نقش **Analyst** بدهید.
- به تأییدکننده نقش **Verifier** (و در صورت نیاز LabManager) بدهید.
- یک نفر نباید هم‌زمان Analyst و Verifier باشد مگر در موارد اضطراری مستند.

> A result must be **verified by someone other than the analyst who produced it.**
> Do not give the same person both Analyst and Verifier for routine work.

## ۳) ماتریس پیشنهادی کارکنان آزمایشگاه تندیس

| فرد / سمت | نقش‌ها | گروه |
|---|---|---|
| مدیر آزمایشگاه | LabManager | LabManagers |
| مدیر فنی / کیفیت | LabManager + Verifier | LabManagers |
| پذیرش و امور مشتریان | LabClerk | LabClerks |
| کارشناس آزمون ۱ | Analyst | Analysts |
| کارشناس آزمون ۲ | Analyst | Analysts |
| تأییدکنندهٔ نتایج | Verifier | Verifiers |
| نمونه‌بردار | Sampler | Samplers |
| مسئول صدور گزارش | Publisher | Publishers |
| ممیز داخلی / بازرس | RegulatoryInspector | — |

> «امور مشتریان» (شکایات/نظرسنجی/پشتیبانی) با نقش **LabClerk یا LabManager**
> قابل دسترسی است (مجوز `ManageBika`).

## ۴) روش ساخت حساب کارمندی (رمز را خودتان می‌گذارید)

> رمز عبور از دست هیچ‌کس جز خودتان رد نمی‌شود. حساب‌ها را خودتان بسازید.

۱. با `admin` وارد شوید.
۲. به این آدرس بروید:
   `http://localhost:8080/senaite/@@usergroup-userprefs`
۳. دکمهٔ **Add User / افزودن کاربر** را بزنید.
۴. نام کاربری، نام و نام خانوادگی، ایمیل و **رمز قوی** را وارد کنید.
۵. در قسمت **Roles/Groups**، گروه یا نقش مناسب از جدول بالا را انتخاب کنید.
۶. ذخیره کنید.
۷. برای هر کارمند، مرحلهٔ ۳ تا ۶ را تکرار کنید.

**تغییر نقش کاربر موجود:** همان صفحه → روی کاربر کلیک کنید → نقش/گروه را
اصلاح کنید → ذخیره.

**تغییر رمز یک کاربر:** همان صفحه → کاربر → فیلد رمز → رمز جدید → ذخیره.

## ۵) LabContact در برابر User — تفاوت مهم

- **User (کاربر ورود):** حساب برای ورود به سیستم و انجام کار (بالا توضیح داده شد).
- **Lab Contact (تماس آزمایشگاه):** پروفایل کارشناس که در گزارش‌ها به‌عنوان
  «انجام‌دهنده/تأییدکننده» چاپ می‌شود. مسیر:
  `http://localhost:8080/senaite/bika_setup/bika_labcontacts`

برای آنکه نام کارشناس در گزارش درست چاپ شود، بهتر است هر کارشناس هم یک
**User** داشته باشد و هم یک **Lab Contact** که به آن User وصل شده باشد
(فیلد Username در فرم Lab Contact).

---

## ۶) چک‌لیست تحویل نقش‌ها

- [ ] حداقل یک حساب **LabManager** غیر از admin ساخته شد.
- [ ] کارشناسان آزمون نقش **Analyst** دارند (نه LabManager).
- [ ] حداقل یک **Verifier** جدا از آنالیست‌ها تعریف شد.
- [ ] پذیرش/امور مشتریان نقش **LabClerk** دارد.
- [ ] از `admin` فقط برای تنظیمات استفاده می‌شود، نه کار روزمره.
- [ ] برای کارشناسانی که در گزارش چاپ می‌شوند، **Lab Contact** به User وصل شد.
