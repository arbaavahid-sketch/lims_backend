# ماتریس نقش‌ها و دسترسی‌ها — آزمایشگاه تندیس (Roles &amp; Access Matrix)

مطابق ISO/IEC 17025 بند ۶.۲ (کارکنان) و بند ۸ (الزامات سیستم مدیریت)، نقش‌ها و
سطوح دسترسی باید تعریف‌شده و مستند باشند. این سند وضعیت پیاده‌سازی‌شده در SENAITE
را شرح می‌دهد.

## نقش‌ها (Roles)

| نقش (سیستمی) | فارسی | مسئولیت |
|---|---|---|
| `Manager` | مدیر سامانه (روت Zope) | فقط پیکربندی فنی/زیرساخت. **نه کار روزمرهٔ آزمایشگاه.** حساب `admin`. |
| `LabManager` | مدیر آزمایشگاه | مدیریت کامل: تنظیمات، تأیید، انتشار، مدیریت کاربران آزمایشگاه |
| `LabClerk` | کارشناس/مسئول دفتری | ثبت نمونه، مدیریت داده‌های پایه (دسترسی به تنظیمات) |
| `Analyst` | آزمونگر | ورود نتیجهٔ آزمون. **بدون دسترسی به تنظیمات سامانه.** |
| `Verifier` | تأییدکننده | تأیید نتایج (تفکیک وظایف: تأییدکننده ≠ واردکنندهٔ نتیجه) |
| `Sampler` | نمونه‌بردار | ثبت نمونه‌برداری |
| `Publisher` | منتشرکننده | انتشار گزارش/گواهی (CoA) |
| `Client` | مشتری | فقط دادهٔ خودش (پرتال مشتری) — در مدل فعلی غیرفعال؛ مشتری از فرم عمومی استفاده می‌کند |

## کاربران فعلی

| کاربر | نقش‌ها |
|---|---|
| `admin` | Manager (روت) — فقط پیکربندی سامانه |
| `manager` | LabManager + Publisher |
| `ali`, `analyst` | Analyst |
| `verifier`, `reviewer` | Verifier |
| `sampler` | Sampler |

## ماتریس دسترسی به بخش‌ها

| بخش | مجوز لازم | چه کسی؟ |
|---|---|---|
| تنظیمات سامانه (`@@lims-setup`) و همهٔ کاشی‌ها | `senaite.core: Manage Bika` | LabManager, LabClerk, Manager |
| داشبوردهای مدیریتی (امور مشتریان، عملکرد آزمونگر، کالیبراسیون، بازنگری اسناد) | `senaite.core: Manage Bika` | LabManager, LabClerk, Manager |
| ابزار حذف امور مشتریان (`@@customer-care-delete`) | `senaite.core: Manage Bika` | LabManager, LabClerk, Manager |
| ورود نتیجهٔ آزمون | Analyst و بالاتر | Analyst, LabManager |
| تأیید نتیجه | Verifier | Verifier, LabManager |
| انتشار گزارش | Publisher | Publisher, LabManager |
| **فرم ثبت درخواست مشتری** (`@@customer-feedback`) | عمومی (بدون ورود) | همه (مشتری) |
| **پیگیری درخواست** (`@@track-request`) | عمومی (بدون ورود) | همه (مشتری، با کد یا لینک توکن‌دار) |

## تفکیک وظایف (Segregation of Duties) — ISO 17025

- **تأییدکننده ≠ واردکنندهٔ نتیجه:** با تنظیم `SelfVerificationEnabled=0` تضمین شده؛
  کاربری که نتیجه را وارد کرده نمی‌تواند همان را تأیید کند.
- **تأیید سند کنترل‌شده ≠ نویسندهٔ آن:** گردش‌کار سند با مجوز «Review portal content»
  گارد شده؛ نویسنده (فقط Modify) نمی‌تواند سند خود را تأیید کند.
- **رسیدگی به شکایت:** فقط کارکنان (Review portal content) می‌توانند وضعیت را تغییر دهند؛
  مشتری فقط ثبت می‌کند.
