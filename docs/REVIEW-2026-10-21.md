# Review: sample conversion and deployment

Scope: sample conversion, catalog queue handling, intake route permissions,
sample date schema, Docker deployment and backup scripts. This is a focused
review, not a certification that the entire application has no defects.

## Changes

- Drain creation indexing, recursively uncatalog before renaming, then
  recursively catalog and drain indexing at the final tracking-code path.
- Use DateSampled (actual collection date), not SamplingDate (expected date).
- Add regression coverage for descendant paths, catalog failure rollback,
  date mapping and missing required selections.

## Validation

- 16 isolated conversion tests pass on Python 3.14.
- XML syntax of all 183 source ZCML files parses successfully.
- The record-literal parser accepts a basic dictionary input.
- Docker daemon is unavailable; Python 2.7 / Plone / ZODB integration tests
  and an image build have NOT run. The isolated tests use API/queue doubles.

## Open findings (not changed)

1. High: src/senaite/core/browser/samplerequest/delete.py disables CSRF,
   accepts request parameters without requiring POST, and explicitly commits
   deletion. A manager following a crafted URL can trigger deletion. Require
   POST plus a validated authenticator; update and test the listing caller.
2. High: src/senaite/core/browser/samplerequest/convert.py disables CSRF and
   its template lacks an explicit authenticator. Require validated tokens
   for this authenticated mutation and test the form before deployment.
3. High: the parent repository tracks multiple backups/*.tar.gz archives.
   Their contents and remote visibility were not inspected. Confirm whether
   these contain production data; handle removal/history cleanup separately.
4. Medium: scripts/backup.sh archives a live data volume without quiescing
   the database or using a database-aware backup. Consistency is not assured
   during writes. Use a supported database backup or a stopped-service snapshot
   and verify restoration on an isolated volume.

## Deployment and acceptance

The application source is a submodule. Pull the parent repository and run
`git submodule update --init --recursive`. Rebuild the application image;
the production compose file uses a prebuilt image, so pulling alone does not
deploy this change. Restart/recreate the service with the rebuilt image.

On an isolated test deployment, convert a request with two analyses and a
known collection date. Confirm the final tracking code in the sample list,
both analysis objects resolve, DateSampled is preserved, and UID/catalog
queries have no old paths or duplicate entries. Repeat submission must not
create a second sample. Exercise catalog failure and concurrent conversion
with the real transaction manager before treating rollback as integration-tested.

Existing broken records are not repaired automatically by this source change.
